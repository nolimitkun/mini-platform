# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

Mini Platform is a **GitOps Kubernetes reference stack**, not an application
codebase. There is no service source code to compile. The repo is a declarative
description of a cluster that **Argo CD** reconciles, combining three kinds of
content:

- `charts/` — **vendored upstream Helm charts**, committed verbatim (Argo CD,
  Vault, VSO, and every platform component). Treat these as third-party; they
  are intentionally not linted or modified here.
- `values/` — **integration overlays**, one `*-values.yaml` per managed release.
  This is where Mini Platform's customizations live. Contains **no credentials**.
- `gitops/` — the **Argo CD app-of-apps** wiring plus Vault secret mappings and
  ingress routes (the only first-party Helm charts in the repo).

## Two invariants that govern every change

1. **Argo CD reconciles Git commits, never the working tree.** Editing an
   overlay or GitOps chart has no effect until it is committed *and pushed* to
   the branch/revision Argo CD tracks. A clean `git status` is a precondition
   for the `--local-source` deploy path.
2. **No credentials in Git.** Vault is the source of truth for all application
   secrets; Vault Secrets Operator (VSO) materializes Kubernetes Secrets from
   it. Never add a Secret manifest or a literal credential to `values/` or
   `gitops/`. New credentials are generated by `scripts/bootstrap-vault-secrets.sh`
   and surfaced via `gitops/vault-resources/`.

## Validation (run before every commit to GitOps wiring)

```bash
./scripts/validate-gitops.sh
```

This is exactly what CI (`.github/workflows/validate.yaml`) runs. It:

- checks every `chartPath`/`valuesFile` referenced by the app-of-apps exists,
- `helm lint`s and `helm template`s the three `gitops/` charts,
- runs `kubeconform` over the rendered manifests, and
- `shellcheck`s `scripts/*.sh`.

`helm` is required; `kubeconform` and `shellcheck` are skipped if absent locally
but always run in CI, so install them to reproduce CI exactly. There is no test
suite beyond this validator — "tests" here means rendering and schema-checking.

## Architecture

Default AI request path: `Open WebUI → LiteLLM → vLLM Router → vLLM`, with
LiteLLM emitting traces to Langfuse. LiteLLM is an OpenAI-compatible gateway
serving the `local-opt125m` model backed by `facebook/opt-125m`.

Supporting subsystems: Vault + VSO (secrets), Ingress NGINX (`.test`
hostnames), Prometheus + Grafana (metrics), MLflow (experiments), Qdrant
(vectors), Spark Operator, Superset → Trino (analytics), Keycloak (identity),
MinIO (S3 object store), all reconciled by Argo CD. Langfuse, MLflow, and
Superset each bring their own isolated stateful dependencies so their upgrades
stay independent of the LiteLLM gateway.

**Vault must be initialized and unsealed before dependent apps go healthy.**
Early Argo CD syncs intentionally show missing-secret failures until Vault is
seeded and the `VaultStaticSecret` resources synchronize — this is expected, not
a bug.

### The app-of-apps and sync waves

`gitops/root-application.yaml` is the single root Argo CD `Application`. It
renders `gitops/mini-platform/` (the app-of-apps chart), whose
`templates/applications.yaml` loops over the `applications:` map in
`gitops/mini-platform/values.yaml` to emit one Argo CD `Application` per release.

Each entry maps a `chartPath` (under `charts/` or `gitops/`) to a `valuesFile`
(under `values/` or `gitops/`) and a **sync wave** that orders rollout:

| Wave | Tier |
| --- | --- |
| `-5` | Argo CD |
| `-4` | Vault, VSO |
| `-3` | Vault secret mappings, stateful deps (postgres, redis, qdrant, minio, spark-operator) |
| `-2` | Keycloak, Langfuse, MLflow, Trino, vLLM |
| `-1` → `0` | Prometheus, Grafana, JupyterHub, Superset |
| `1` → `3` | LiteLLM, then Open WebUI, then ingress routes |

All generated Applications use `automated` sync with `prune: true`,
`selfHeal: true`, `CreateNamespace=true`, and `ServerSideApply=true`.

### Secret flow

`scripts/bootstrap-vault-secrets.sh` writes random credentials into the Vault
KV mount `mini-platform/`. `gitops/vault-resources/values.yaml` lists secret
*names*; its template renders a `VaultStaticSecret` per name that VSO syncs into
a like-named Kubernetes Secret. The two lists must agree: a secret a workload
needs must be **both** written by the bootstrap script **and** listed in
`vault-resources`. Note the shared `litellm-langfuse` secret — Langfuse's
headless init provisions the starter org/project from those keys and LiteLLM
reads the same keys for tracing, so no browser setup is needed.

## Common conventions / recipes

**Adding or changing a managed component:** edit the matching `values/*.yaml`
overlay (not the vendored chart). To add a *new* release: drop the upstream
chart under `charts/`, add an overlay under `values/`, add an `applications:`
entry in `gitops/mini-platform/values.yaml` with an appropriate `wave`, and (if
it needs credentials) add a secret to `bootstrap-vault-secrets.sh` and its name
to `gitops/vault-resources/values.yaml`. To expose it in a browser, add a route
in `gitops/ingress-resources/values.yaml`.

**Pointing at a fork/branch:** the `repoURL`/`targetRevision` appear in several
files that must stay in sync. Never hand-edit them — run:

```bash
./scripts/set-repo.sh --repo-url https://github.com/<owner>/mini-platform.git --revision <branch>
```

It rewrites `gitops/root-application.yaml`, `gitops/mini-platform/values.yaml`,
and the `scripts/deploy-minikube.sh` defaults together.

**Deploying / bootstrapping:** `scripts/deploy-minikube.sh` automates the full
Minikube + Argo CD + Vault bring-up (key flags: `--reset`, `--local-source`,
`--no-gpu`, `--rotate-secrets`). The default `values/vllm-values.yaml` requests
an NVIDIA GPU — for CPU-only work, edit that overlay or pass `--no-gpu`.
`scripts/port-forward-services.sh` exposes services on the Minikube host
(`--mode lan` for LAN access).

The README is the authoritative deployment/operations reference and includes the
full manual bootstrap (namespace → Argo CD → root app → Vault init → seed),
service endpoints, and credential-retrieval commands. Consult it before changing
deploy/bootstrap behavior.

## Notes

- This is a **local reference stack**, not production: in-cluster TLS is off,
  Vault uses manual single-key unseal, and Trino/Prometheus/databases/vLLM are
  cluster-internal with no auth. Don't assume hardening that isn't there.
- `tools/` holds optional utility workloads (e.g. `net-tools.yaml`) applied
  manually, outside the GitOps reconciliation.
- `.github/workflows/claude.yml` and `claude-code-review.yml` wire up the Claude
  GitHub app; `validate.yaml` is the real CI gate.
